# WSL Remote Setup

**집이나 사무실의 Windows PC를 Linux 작업 서버로 만들고, 노트북에서 SSH와 원격 데스크톱으로 접속하게 해 주는 프로그램입니다.**
EXE 파일 하나를 실행하고 질문에 답하면 필요한 설정을 단계별로 진행합니다.

> 데스크톱에서 일하다가 소파나 침대에서 노트북으로 이어서 작업하고 싶을 때가 있습니다.
> 휴대폰 앱으로는 부족하고 큰 화면이 필요한 경우, 이 프로그램으로 노트북에서 데스크톱의 Linux 환경에 바로 들어갈 수 있습니다.

## 무엇을 해 주나요

```mermaid
flowchart LR
    A["노트북<br/>(소파·침대)"] -- "같은 공유기(Wi-Fi)" --> B["이 PC (Windows)<br/>1004번으로 받은 접속을"]
    B -- "자동 전달" --> C["WSL 안의 Ubuntu<br/>SSH 서버"]
```

- **Linux 설치**: Windows 안에 Ubuntu(WSL)를 설치하고 사용자를 만듭니다.
- **SSH 접속 준비**: Ubuntu 안에 SSH 서버를 설치하고, 다른 기기에서 들어올 수 있는 통로(기본 1004번)를 엽니다.
- **집 안에서만 열기**: 같은 공유기에 연결된 기기만 허용합니다. 인터넷 전체에는 열지 않습니다.
- **끊기면 스스로 복구**: WSL이 꺼지거나 주소가 바뀌어도, 재부팅해도 1분 안팎에 다시 연결합니다.
- **로그인 전 접속(선택)**: PC를 켜기만 하면 로그인하지 않아도 약 1분 뒤부터 접속할 수 있습니다.
- **절전 점검**: PC가 잠들어 접속이 끊기지 않도록 알려 주고, 원하면 전원 연결 시 절전을 끕니다.
- **노트북 접속 도우미**: 노트북 쪽 SSH 키·접속 이름·원격 데스크톱 바로가기를 파일 하나로 준비합니다.
- **되돌리기**: 단계마다 영향을 알려 주고 확인을 받으며 원래대로 되돌립니다. Ubuntu를 지우기 전에는 백업할지 묻습니다.

## 준비물

| 항목 | 설명 |
|---|---|
| Windows 10/11 **Pro** (64비트) | Home은 원격 데스크톱 없이 SSH만 됩니다. |
| 관리자 계정 | 중간에 '관리자 권한' 확인 창(UAC)이 뜹니다. |
| 인터넷 연결 | WSL과 Ubuntu를 내려받습니다(수백 MB). |
| 같은 공유기 | 노트북과 이 PC가 같은 공유기(Wi-Fi)에 있어야 합니다. |
| 30분 정도 | 처음 설치라면 재부팅이 한 번 필요할 수 있습니다. |

다른 프로그램(Git, .NET 등)은 필요 없습니다. EXE 파일 하나면 됩니다.

## 빠르게 시작하기

1. `WslRemoteSetup.exe`를 **더블클릭**합니다(일반 창으로 실행).
2. 메뉴에서 **1(새로 설치)** 를 입력하고 Enter를 누릅니다.
3. 질문에 답합니다. 대부분은 **Enter(기본값)** 로 충분합니다.
4. 관리자 창이 열리면 UAC에서 '예' → 새 창에서 **Y** → 끝나면 Enter로 닫습니다.
5. 마지막에 나오는 상태 화면이 모두 **정상**이면 노트북에서 접속해 봅니다.

중간에 멈춰도 괜찮습니다. 다시 실행해서 1번을 고르면 이어서 진행합니다.

### 설치 질문 6가지

| 질문 | 기본값 (Enter) | 이렇게 고르세요 |
|---|---|---|
| 다른 기기에서 접속할 포트 | 1004 | 다른 프로그램이 쓰고 있으면 빈 번호를 추천해 줍니다 |
| WSL을 쓸 Windows 계정 | 지금 로그인한 계정 | 평소 이 PC에 로그인하는 계정 |
| Ubuntu 사용자 이름 | linux_admin | 영문 소문자로 시작하는 이름 |
| SSH 로그인 방식 | 비밀번호 또는 키 | mRemoteNG 같은 도구는 이쪽이 편합니다 |
| SSH 말고 더 열 포트 | 아니오 | 웹 서버 등을 열 때만 '예' |
| 로그인 전에도 접속 | 아니오 | 서버처럼 켜 두는 PC라면 '예' |

IP 주소와 원격 데스크톱 포트는 묻지 않고 지금 PC 설정을 그대로 씁니다.

## 노트북에서 접속하기

먼저 서버 PC의 주소를 확인합니다(서버 PC의 명령 프롬프트에서 `ipconfig` → 'IPv4 주소').
아래 예시의 `192.168.1.222`는 예시 주소입니다. 실제 주소로 바꿔 입력하세요.

- **터미널(PowerShell)**
  ```bash
  ssh -p 1004 linux_admin@192.168.1.222
  ```
- **mRemoteNG · PuTTY**: 호스트 = 서버 PC 주소, 포트 = 1004, 프로토콜 = SSH 버전 2, 사용자 = linux_admin
- **원격 데스크톱(큰 화면)**: `서버 PC 주소:원격 데스크톱 포트`로 접속합니다(기존 설정 그대로).

> 접속이 안 되면 **주소 끝자리**부터 다시 확인하세요. 끝자리 하나만 달라도 연결되지 않습니다.

### (선택) 노트북 접속 도우미

1. 서버 PC에서: `WslRemoteSetup.exe export-client` → 바탕화면에 `이름.wrs.json`이 생깁니다.
2. 그 파일과 EXE를 노트북으로 복사합니다.
3. 노트북에서: `WslRemoteSetup.exe client 이름.wrs.json` → 질문마다 Enter.

SSH 키 만들기, 서버 확인 정보 등록, `ssh 이름` 한 줄로 접속하게 등록, 원격 데스크톱 아이콘까지 준비합니다.
연결 정보 파일에는 비밀번호와 개인키가 들어가지 않습니다. 노트북에는 관리자 권한이 필요 없습니다.

## 평소 관리

메뉴(더블클릭)로 할 수 있고, EXE가 있는 폴더에서 PowerShell을 열어 명령으로도 할 수 있습니다.

| 하고 싶은 일 | 메뉴 / 명령 |
|---|---|
| 상태 보기 | 메뉴 2 · `.\WslRemoteSetup.exe status` |
| 연결 복구 | 메뉴 3 (빠진 것만 다시 확인하고 고칩니다) |
| 잠시 멈춤 / 다시 켜기 | 메뉴 5 · `pause` / `resume-monitoring` |
| 잠들지 않게 | `power keep-awake` (되돌리기: `power restore`) |
| 로그인 전 접속 켜기·끄기 | `autostart prelogin-on` / `prelogin-off` (관리자 창) |
| 되돌리기 | 메뉴 6 · `uninstall` |
| 전체 명령 보기 | `help` |

작업 기록은 `%LOCALAPPDATA%\WslRemoteSetup\logs\history.log`에 남습니다(관리자 작업은 `C:\ProgramData\WslRemoteSetup\logs`).

## 되돌리기

메뉴 6(또는 `uninstall`)을 **일반 창**에서 실행합니다. 원하지 않는 단계는 `n`으로 건너뜁니다.

1. 외부 연결 닫기: 다른 기기에서 SSH로 들어올 수 없게 됩니다(원격 데스크톱은 그대로).
2. 자동 실행 중지: 백그라운드 프로그램·자동 실행·로그인 전 접속을 지웁니다.
3. Ubuntu 안 SSH 설정 되돌리기: 이 프로그램이 만든 설정과 등록한 키만 지웁니다.
4. (선택) Ubuntu 삭제: 기본값은 '아니오'입니다. 지우기 전에 **백업 파일**로 저장할지 묻습니다.
5. 설치 이력 안내: 지우지 않은 프로그램과 직접 지우는 방법을 알려 줍니다.

백업해 둔 Ubuntu는 이렇게 되살립니다(사용자·설정까지 그대로):

```bash
wsl --import Ubuntu-24.04 "%LOCALAPPDATA%\WSL\Ubuntu-24.04" "백업파일.tar"
```

## 안전하게 만든 부분

- **집 안에서만**: 방화벽은 같은 공유기 범위와 '개인 네트워크'에서만 허용합니다. 인터넷 공개는 하지 않습니다.
- **비밀번호를 보지 않음**: 비밀번호는 Linux·SSH 프로그램이 직접 묻습니다. 이 프로그램은 비밀번호를 읽거나 저장하지 않습니다.
- **바꾸기 전에 확인**: 시스템을 바꾸는 단계는 무엇이 바뀌는지 먼저 보여 주고 [Y/n] 확인을 받습니다.
- **기존 설정 보존**: IP·원격 데스크톱 포트·기존 계정과 방화벽 규칙은 바꾸지 않습니다.
- **만든 것만 지움**: 되돌리기는 이 프로그램이 만든 것만 지웁니다.
- **관리 권한 분리**: 백그라운드 프로그램은 관리자만 고칠 수 있는 설정만 믿고, 일반 사용자 쪽 요청은 정해진 범위 안에서만 처리합니다.

## 지금 상태와 한계

- 버전 0.1(개발 중). Windows 11 Pro(x64) PC 한 대에서 설치·재부팅 복구·로그인 전 접속·노트북 접속을 실제로 확인했습니다.
- 아직 실제로 확인하지 않은 것: 깨끗한 새 PC에서 처음부터 끝까지 설치, 되돌리기 전 과정, 노트북 접속 도우미, 주소가 자동으로 바뀌는 환경(DHCP), ARM64 PC.
- 같은 공유기 안(LAN)에서만 접속하도록 만들었습니다. 밖(인터넷)에서 접속하는 기능은 없습니다.
- Wi-Fi PC에서 로그인 전 접속을 쓰려면 Wi-Fi가 '모든 사용자'용으로 저장되어 있어야 합니다.
- 서명하지 않은 EXE라 처음 실행 때 'Windows의 PC 보호' 창이 뜰 수 있습니다. 직접 받은 파일이 맞는지 확인한 뒤 '추가 정보 → 실행'을 누릅니다.

## 직접 빌드하기 (개발자용)

[.NET 10 SDK](https://dotnet.microsoft.com/)가 필요합니다.

```bash
dotnet test WslRemoteSetup.slnx
dotnet publish src/WslRemoteSetup -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o artifacts/release
```

ARM64용은 `-r win-arm64`로 만듭니다. 설치 매뉴얼(PowerPoint)은 다음 명령으로 만들 수 있습니다.

```bash
dotnet run --project tools/ManualBuilder -- artifacts/manual/WSL_Remote_Setup_설치매뉴얼.pptx
```

| 폴더 | 내용 |
|---|---|
| `src/WslRemoteSetup` | 실행 프로그램(메뉴·설치·되돌리기·백그라운드 관리) |
| `src/WslRemoteSetup.Core` | 판단 로직(검사·계획·상태), 시스템을 바꾸지 않는 부분 |
| `resources/linux` | Ubuntu 안에서 실행하는 고정 스크립트 |
| `tests` | 단위·통합 테스트 |
| `tools/ManualBuilder` | 설치 매뉴얼 생성 도구 |
| `docs` | 개발 계획, 진행 상황, 시험 기록, 설계 결정(ADR) |

문서에 나오는 주소·계정·포트는 모두 **예시 값**입니다.
