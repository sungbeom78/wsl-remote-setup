# ADR 0008 — 이 PC 주소 고정 마법사(고급)

- 상태: 채택 (후속 범위, 사용자 선택 2026-10-18). 코드·단위 테스트 완료, 실기 NOT_TESTED(G2는 이미 고정 주소)

## 결정

- 명령은 `network plan|apply|revert`이다. 설치 마법사는 DHCP일 때만 이 기능을 제안하며, 기본값은 "아니요"다.
- **기본은 지금 주소를 그대로 고정한다.** 게이트웨이와 DNS도 지금 값을 유지한다. 주소가 바뀌지 않으므로 원격 연결이 끊기지 않는다.
- 다른 주소를 요청하면 다음 경우 차단한다.
  - 같은 LAN 범위가 아니다.
  - 네트워크 주소, 브로드캐스트 주소, 게이트웨이 주소다.
  - ping 2회에 응답이 있다(이미 다른 기기가 쓰는 중).
  - 이미 고정 주소다.
  - 게이트웨이가 없다.
  - 범위가 /8~/30 밖이다.
- **적용 후 확인:** 새 주소가 붙고 공유기가 ping에 응답하는지 15초 동안 확인한다. 실패하면 즉시 자동 할당으로 되돌린다.
- **자동 원복:** 주소가 바뀐 경우, 관리자 창이 5분 동안 Enter를 기다린다. 사용자는 RDP로 새 주소에 다시 접속해 같은 Windows 세션의 그 창에서 Enter를 누른다. 시간 안에 누르지 않으면 자동 할당으로 되돌린다. 별도의 SYSTEM 예약 작업은 만들지 않는다.
- **기록:** 상태 파일에 `static-ip` 소유 리소스와 이전 값(DHCP)을 남긴다. `network revert`와 `uninstall`(선택 단계, [y/N])은 이 도구가 고정한 주소만 자동 할당으로 되돌린다.

## 대안

- **공유기 DHCP 예약:** 가장 근본적인 해결책이지만 공유기마다 방법이 달라 자동화 범위 밖이다. 화면에서 계속 권장한다.
- **SYSTEM 예약 작업으로 원복:** 보호 경로의 실행 파일이 필요하고 관리할 리소스가 늘어난다. 같은 세션의 창이 직접 대기하는 방식이 더 단순하다.

## 제한

- 공유기의 자동 할당 범위를 알 수 없다. 그래서 고정한 주소가 나중에 다른 기기에 할당될 가능성은 경고만 한다.
- 주소를 바꾸면 SSH 연결 통로를 새 주소에 맞춰야 한다. 주소 따라가기를 켰다면 자동으로 옮겨지고(ADR 0007), 아니면 `install`을 다시 실행하라고 안내한다.
