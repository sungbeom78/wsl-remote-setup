# ADR 0004 — 적용 확인 입력: Y/n (기본 Y)

- 상태: 채택 (사용자 결정, 2026-10-18)

## 맥락

`forward apply`는 한글 단어 `적용`을 입력받아 확인했다. 그런데 G2의 승격 Windows PowerShell 5.1 콘솔에서는 입력 코드페이지(CP949)와 프로그램의 UTF-8 설정이 서로 달라, 사용자가 `적용`을 정확히 입력해도 다른 문자열로 읽혔다. 그 결과 적용이 취소됐다(exit 3, 변경 없음).

사용자는 확인 입력을 `Y/n`(기본값 Y)으로 바꾸도록 요청했다.

## 결정

- 확인 입력은 ASCII `[Y/n]`으로 받는다. 빈 입력(Enter)·`y`·`yes`는 진행, `n`·`no`는 취소로 처리한다. 그 밖의 입력은 3회까지 다시 묻고, 그래도 올바르지 않으면 취소한다.
- 입력이 리디렉션된 비대화형 실행에서는 확인을 받을 수 없으므로 진행하지 않는다. 이때 종료코드는 3(`UserInputRequired`)이다.
- 취소하면 종료코드 5(`Canceled`)로 끝내 입력 불가(3)와 구분한다.

## 개발 계획과의 관계

이 결정은 개발 계획 6.3절의 "Enter만으로 위험 변경에 동의한 것으로 처리하지 않는다"를 사용자 결정으로 바꾼다. 위험을 줄이기 위해 다음을 유지한다.

- 확인 직전에 변경 전·후 계획을 반드시 출력한다.
- 계획에 차단 사유가 있으면 확인 단계로 가지 않는다.
- 승격(UAC)이 별도의 명시적 동의 단계로 남아 있다.
- 일괄 승인 옵션(`--yes`)이나 비대화형 자동 승인은 제공하지 않는다.
