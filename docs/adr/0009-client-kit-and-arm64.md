# ADR 0009 — 접속 도우미(client)·연결 정보 파일·ARM64·절전 점검

- 상태: 채택 (사용자와 다음 작업으로 결정, 2026-10-18)

## 맥락

사용자가 그린 활용 장면은 **데스크톱이나 미니 PC를 작업 서버로 두고, 소파·침대의 노트북에서 큰 화면으로 작업하는 것**이다. 모바일 앱만으로는 이 경험을 대신하기 어렵다.

G2 실사용에서는 접속하는 쪽 준비가 번거로웠다.
- 키 생성
- `~/.ssh/config` 작성(포트 7389와 1004 혼동)
- 공개키 전달
- 서버 키 지문 확인
- RDP 설정

"후속 범위"로 남겨 둔 ARM64는 서버보다 **접속하는 쪽(ARM 노트북)**에서 의미가 크다.

## 결정

1. **`export-client`(서버)**
   - 접속에 필요한 공개 정보만 담은 연결 정보 파일(`*.wrs.json`)을 만든다. 담는 항목은 이름, 주소, SSH 포트, Linux 사용자, RDP 포트·사용자, SSH 서버 키 지문(ED25519), 만든 시각이다.
   - 비밀번호·개인키·설치 ID·SID는 넣지 않는다.
2. **`client` 모드(노트북, 같은 EXE)**
   - 연결 정보 파일을 검증한 뒤 다음을 단계별로 한다(변경마다 [Y/n]).
     - 키가 없으면 `ssh-keygen`(passphrase는 사용자가 직접 입력)
     - `known_hosts`에 지문으로 확인한 서버 키를 미리 등록 — 처음 접속할 때 yes/no 질문이 나오지 않게 한다.
     - `~/.ssh/config`에 이 도구 표식이 있는 Host 블록을 추가하거나 갱신한다(다른 블록은 보존, 백업).
     - 비밀번호로 한 번 접속해 공개키를 등록한다.
       - 원격 명령은 고정 문자열이다.
       - 키는 표준입력으로 넘긴다.
       - 비밀번호는 ssh가 직접 묻는다.
     - RDP 바로가기(`.rdp`)를 만든다.
     - 키로 접속되는지 확인한다.
   - 서버 키 지문이 파일과 다르면 중단한다(중간자 방지).
3. **ARM64**
   - win-arm64 단일 EXE를 함께 만든다.
   - client 모드가 주 용도다. ARM 서버 모드는 시험 장비가 없어 NOT_TESTED로 표기한다.
4. **절전 점검**
   - `status`에서 "전원 연결 시 N분 뒤 절전"을 쉬운 말로 경고한다.
   - 선택 옵션 "전원 연결 시 절전 안 함"을 제공하며, 바꾸려면 승인이 필요하다.
   - Wake-on-LAN은 보통 유선 랜에서만 되므로 안내만 한다.

## 이번에 종료한 것

로그인 전 무인 실행은 G2 내부 경로가 부팅 후 45초에 준비됐다. 그러나 로그인 전 외부 LAN에서 들어오는 연결이 sshd에 도달하지 못했고, 원인을 확정하지 못했다. 사용자 결정으로 POC를 종료한다. 1.0 지원 범위는 "로그인 후"로 유지한다. 근거는 TEST_RESULTS 2026-10-18 20:23 항목이다.

## 제한

- client 모드는 Windows 노트북(x64/ARM64)만 지원한다. macOS·Linux 노트북에는 같은 내용을 수동 안내문으로 제공한다(연결 정보 파일 + 명령 예시).
- 공개키 등록 단계는 서버가 비밀번호 로그인을 허용할 때만 자동으로 할 수 있다. 키 전용 서버에는 기존 방식(서버에서 붙여 넣기)을 안내한다.

## 구현 메모 (2026-10-18)

- 공개키 등록은 표준입력 대신 **고정 형식 원격 명령의 인수**로 넘긴다. 공개키는 비밀이 아니고, 형식(키 종류·base64·지문 계산)을 검사하고 주석의 특수문자를 제거해 셸 주입을 막는다. 이렇게 하면 콘솔 입력을 ssh 비밀번호 질문에 그대로 쓸 수 있다.
- 노트북 `~/.ssh/config`에 사용자가 직접 만든 같은 이름의 Host가 있으면(대소문자 무시) 덮어쓰지 않고 멈춘다. 기본 이름은 서버 PC 이름이다(G2는 SERVERPC).
