# ADR 0011 — 서비스 포트 관리(WSL 안 서비스를 다른 기기에서 쓰기)

- 상태: 채택 (사용자와 방향 합의, 2026-10-20)

## 맥락

WSL 안에서 여러 서비스(웹 개발 서버, Jupyter, Docker 컨테이너 등)를 돌리고, 같은 공유기의 다른 기기에서 쓰고 싶다.

사용자 요구:
- Windows나 WSL을 다시 시작해도 포트와 방화벽이 유지되어야 한다.
- 한 번 설정한 포트는 WSL 안 서비스가 꺼져 있어도 지우거나 막지 않는다. 시작할 때 동작 여부를 확인해 알려 주면 좋다.
- 삭제할 수 있어야 한다.
- 설정한 포트를 즉시 연결하는 기능이 있으면 좋다.

## 결정

1. **범위는 "연결 통로 관리"까지**로 한다. 서비스 실행·감시(systemd/docker), 도메인·HTTPS, 인터넷 공개는 하지 않는다.
2. 기존 "추가 서비스 포트"를 그대로 쓴다. 보호 정책 `Services`에 기록하고, 서비스가 SSH와 같은 WSL 대상으로 옮기며, 같은 공유기만 허용하는 방화벽 규칙을 둔다. 이렇게 하면 재부팅이나 WSL 주소 변경 뒤에도 백그라운드 연결 관리 프로그램이 유지한다.
3. 메뉴 **7. 서비스 포트 관리**(`ports`)를 둔다.
   - 목록: 이름, 외부 포트, WSL 포트, 통로(이 PC 수신), WSL 서비스(응답 여부)를 보여 준다.
   - 추가: WSL 안 `ss -ltnpH`로 열린 포트를 찾아 번호로 고른다. 직접 입력도 된다.
     - 127.0.0.1에만 열린 서비스는 "외부에서 접속되지 않음"을 알리고 설정 방법(0.0.0.0)을 안내한다.
     - DB 포트(5432, 3306 등)는 한 번 더 경고한다.
     - 실제 변경은 관리자 창의 `forward add-service`가 한다.
   - 삭제: 관리자 창의 `forward remove-service`가 한다. 통로와 방화벽 규칙만 지우고 WSL 서비스는 그대로 둔다.
   - 지금 연결(`ports connect`): WSL을 켜고 현재 주소를 백그라운드 프로그램에 요청 채널로 알린다. 관리자 권한은 필요 없다.
4. 갱신 간격 제한(30초) 안의 요청이어도 SSH 대상이 같으면 추가 서비스 통로를 채운다. 그래서 "지금 연결"이 빠진 포트를 바로 복구한다.
5. 서비스 꺼짐은 오류로 보지 않는다.
   - `status`: "열려 있음 · WSL 서비스 꺼짐(켜면 바로 연결)"으로 표시하고 종합 판정을 낮추지 않는다.
   - 백그라운드 프로그램: 시작 뒤 SSH 경로가 처음 살아날 때 한 번 서비스별 응답 여부를 기록한다.

## 대안

- **WSL 미러 네트워크 모드**(`networkingMode=mirrored`): 포트별 통로가 필요 없다. 다만 계정의 WSL 네트워크 전체가 바뀌고, 일부 VPN·Docker 환경에서 문제가 있다. 이번에는 채택하지 않고 따로 실험한다.
- **서비스 실행까지 관리**: 서비스 종류마다 대응이 필요해 범위가 끝없이 넓어지므로 채택하지 않는다.

## 제한

- TCP만 지원하고, 추가 서비스는 10개까지다.
- 127.0.0.1에만 열린 서비스는 통로가 있어도 접속되지 않는다. 예: Docker `-p 127.0.0.1:9001:…`.
- 추가·삭제는 관리자 창(UAC)이 필요하다.
